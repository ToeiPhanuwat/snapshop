# Flow ข้อมูล: Shopee Affiliate → เว็บเปรียบเทียบราคา

ฉบับปัจจุบัน (อัปเดต 2026-11-18 รอบกลุ่ม R) ใช้แทนบรีฟเดิม (2026-11-12) ส่วนที่เปลี่ยนไปจากบรีฟดูได้ที่ [บันทึกการตัดสินใจ](#บันทึกการตัดสินใจ)
ศัพท์: [GLOSSARY.md](GLOSSARY.md) · กฎนำเข้าในระบบ: [README.md](../README.md#กฎการนำเข้า-สรุป)

## ภาพรวม

```
F1  ลิงก์ affiliate (พอร์ทัล Shopee Affiliate) ─ แยก namePrefix + กลุ่ม E/R ─ ไฟล์ CSV ─ inbox/ ─ พรีวิว ─ นำเข้า ─┐
                                                                                                              │
                      ┌──────────────────────── ระบบดึง feed ของ Shopee อัตโนมัติ (ราคา, ประเภทร้าน, รูป, ...) ◄─┤
                      │                         admin REVIEW กลุ่ม R (รวมกลุ่ม E เข้ากลุ่ม R) ◄─────────────────┘
                      └─ เก็บในตาราง marketplace_product ─ API ─ เว็บ
```

| ขั้น | ทำอะไร | ใครทำ (ตอนนี้) | ผลลัพธ์ |
|---|---|---|---|
| F1 | กดปุ่ม "รับลิงก์แบบทีเดียวทั้งหมด" ในพอร์ทัล | ผู้ใช้ | ไฟล์ CSV (≤ 100 รายการต่อไฟล์) |
| แยกชนิดสินค้า | แยก `namePrefix`, ใส่กลุ่ม E (รหัสกลุ่ม / ชื่อกลุ่ม) และกลุ่ม R (รหัสกลุ่มตามกฎ / ชื่อกลุ่มตามกฎ) | ผู้ใช้ (หรือ Claude) | ไฟล์พร้อมนำเข้า |
| ส่งเข้าระบบ | วางไฟล์ใน `inbox/` | Claude หรือผู้ใช้ | ไฟล์รอนำเข้า |
| พรีวิว + นำเข้า | ดูผลก่อน แล้วกดนำเข้าหรือทิ้ง ที่ `/admin/inbox` | admin | ข้อมูลใน PostgreSQL |
| ดึง feed | หลังนำเข้าเสร็จ ระบบหารายการที่ต้องดึงจาก feed แล้วเติมข้อมูล | ระบบ (อัตโนมัติ) | ราคาที่ขาด, ประเภทร้าน, รูป, stock, rating |
| REVIEW กลุ่ม R | เทียบกลุ่ม R กับกลุ่ม E ติ๊กกลุ่ม E ที่จะรวม แล้วยืนยันที่ `/admin/rule-groups` | admin | รายการกลุ่ม R ขึ้นเว็บ |
| แสดงผล | API → Next.js | ระบบ | เว็บฝั่ง user / admin |

ข้อตกลง: Claude ไม่ใช้รหัสผ่านหรือคีย์ admin ของระบบ และไม่ทำ automation ที่พรางตัวเป็นคนบน Shopee
**F2 เลิกใช้แล้ว** (เดิมคืออ่านการ์ดสินค้าจากหน้าค้นหา ซึ่งผิดกฎ) ข้อมูลที่เคยมาจาก F2 มาจาก feed แทน

## F1 — ลิงก์ affiliate จากพอร์ทัล

- ปุ่ม "รับลิงก์แบบทีเดียวทั้งหมด" เลือกได้ครั้งละ ≤ 100 รายการ จึงได้หลายไฟล์ (ชุดตัวอย่าง 192 รายการ = 2 ไฟล์)
- คอลัมน์: `รหัสสินค้า, ชื่อสินค้า, ราคา, ขาย, ชื่อร้านค้า, อัตราค่าคอมมิชชัน, คอมมิชชัน, ลิงก์สินค้า, ลิงก์ข้อเสนอ`
- `ลิงก์สินค้า` = `https://shopee.co.th/product/{shopId}/{itemId}` (ระบบดึง shop_id จากตรงนี้ และตรวจว่า itemId ตรงกับรหัสสินค้า)
- `ลิงก์ข้อเสนอ` = ลิงก์ affiliate สั้น `s.shopee.co.th/...` สร้างใหม่ทุกครั้งที่กด จึงไม่นับเป็นการเปลี่ยนแปลงของสินค้า
- ไม่ใช้ Sub_id (ยังไม่จำเป็นเมื่อมีหมวดเดียว; ใช้แยกยอดคลิก/ออเดอร์ตามตำแหน่งปุ่มได้ในอนาคต)
- ข้อควรระวัง: ราคาบางแถวเป็นตัวย่อ ("1.0พัน") — ระบบรอราคาจาก feed (ดู [ราคา](#ราคา)), ยอดขายส่วนใหญ่เป็นตัวย่อ ("200พัน+"), คอมมิชชันมี "฿", อัตรามี "%"

## Feed ของ Shopee (แทน F2)

- ลิงก์ feed เป็นความลับ ตั้งผ่านตัวแปรสภาพแวดล้อม `FEED_URL` (ไม่เก็บใน repo); ว่าง = ปิดการดึงอัตโนมัติ
- ลิงก์ feed ตอบ 302 ไปยังที่เก็บไฟล์จริง ระบบตาม redirect ให้เอง (ยกเว้นจาก https ลงไป http)
- feed เป็น CSV ขนาดราว 4 GB (~20 ล้านแถว) ระบบอ่านจากลิงก์โดยตรงแบบ stream ไม่เก็บไฟล์ลงเครื่อง และ**หยุดอ่านทันทีเมื่อเจอครบทุกรายการที่ขอ**
- คอลัมน์ที่ใช้: `itemid, shopid, price` (ก่อนลด), `sale_price` (หลังลด), `stock, item_rating, shop_rating, is_official_shop, is_preferred_shop, image_link`
- ประเภทร้านมาจาก feed: `Official shop` → Mall, ไม่ใช่แต่ `Preferred shop` → ร้านแนะนำ, นอกนั้น → ทั่วไป (ข้อมูลประเภทร้านที่ scrape มาก่อนหน้าถูกล้างทิ้ง)
- รูปมาจาก `image_link` (เก็บลิงก์ ไม่ดาวน์โหลดรูป); รายการไม่มีรูปแสดง "ยังไม่มีรูป"; ถ้า feed ไม่มีรูปของรายการนั้น ไม่ทับรูปเดิมที่มี
- ถ้า `shopid` ใน feed ไม่ตรงกับที่เก็บไว้ ข้ามแถวนั้น

### เมื่อไรที่ระบบดึง feed

หลังนำเข้า F1 สำเร็จ (commit แล้ว) ระบบดึง feed ให้รายการเหล่านี้: รายการใหม่, รายการที่ราคา F1 เปลี่ยน, รายการที่ราคา F1 เป็นตัวย่อ (เทียบเองไม่ได้ จึงดึงทุกรอบ), และรายการที่ยังรอราคา
รายการที่ราคาเท่าเดิมไม่ถูกดึงใหม่ (stock/rating จึงไม่สดเอง) — admin กด "ดึงรายการที่ค้างจากฟีด" ที่หน้า `/admin` เพื่อดึงรายการที่ยังรอราคาหรือไม่เคยดึงได้
ระหว่างมีรอบ "กำลังดึง" (ไม่ว่าเริ่มจากการนำเข้าหรือจากปุ่ม) ปุ่มดึงที่หน้า `/admin` จะ disable และหน้านั้นโหลดสถานะใหม่เองทุก 1 นาทีจนรอบเสร็จ — แถว "กำลังดึง" ถูกบันทึกก่อนระบบตอบกลับ จึงเห็นทันทีเมื่อหน้าโหลดใหม่
ทำทีละงานบนเธรดเดียว นอก transaction แล้วเขียนผลใน transaction สั้น ๆ ที่ใช้ล็อกเดียวกับการนำเข้า ทุกรอบบันทึกใน `feed_sync_run` (เสร็จ / ไม่ครบ / ถูกจำกัด 429 / ล้มเหลว) แสดงที่หน้า admin ระบบไม่ลองซ้ำเอง (เคยโดน 429 เมื่อโหลดถี่)

### ราคา

- F1 ราคาเป็นตัวเลข: ใช้ราคา F1 ตามเดิม feed ไม่เทียบและไม่แทนที่ (ผู้ใช้เทียบเองที่หน้าเว็บ)
- F1 ราคาเป็นตัวย่อ: แถวสถานะ `PRICE_PENDING` (ซ่อนจากเว็บ ไม่ใช่ REVIEW) → feed ให้ `sale_price` แล้วเป็น `OK`; รอบถัดไปถ้า `sale_price` ต่างจากที่เก็บไว้ จะเกิดเวอร์ชันราคาใหม่ (ประวัติราคา)
- feed ไม่มี `sale_price` หรือไม่พบรายการ: ยังเป็น `PRICE_PENDING` ต่อไป

## แยกชนิดสินค้า

กลุ่ม = รายการสินค้าชนิดเดียวกันที่ขายหลายร้าน ใช้เปรียบเทียบราคา (2026-11-18) **สินค้าทุกรายการเก็บ 2 กลุ่ม**:
1. **กลุ่ม E — ชื่ออังกฤษตรงกัน:** normalize ชื่อ (ตัวพิมพ์เล็ก, ตัดเครื่องหมาย/ช่องว่างซ้ำ, ตัดข้อความโปรโมชันภาษาไทย) ตรงกันถือเป็นชนิดเดียวกัน **ขนาดต่างกันถือเป็นชนิดเดียวกัน** (15 ml กับ 16 ml) — ทุกรายการมี
2. **กลุ่ม R — กฎคำระบุสูตร:** ใช้คำ/รหัสสูตรในชื่อ (activeIN, U9.9, MC1, G89, P55, 28D, 711, BarrierX, Retinal-X, Bakuchiol, Astaxanthin ฯลฯ) รวมชื่อที่ต่างกันเล็กน้อย — บางรายการมี

รายการที่มีแค่กลุ่ม E ขึ้นเว็บทันที รายการที่มีกลุ่ม R ต้องผ่าน REVIEW เทียบกับกลุ่ม E ก่อน (ยกเว้นกลุ่ม R เท่ากับกลุ่ม E หนึ่งกลุ่มพอดี)

คอลัมน์กลุ่มในไฟล์:

| คอลัมน์ | ค่า |
|---|---|
| `รหัสกลุ่ม` | ป้ายกลุ่ม E ในไฟล์: `E001…` — **ใช้แค่ภายในไฟล์นั้น** ระบบไม่เก็บ |
| `ชื่อกลุ่ม` | ชื่อกลุ่ม E |
| `รหัสกลุ่มตามกฎ` | ป้ายกลุ่ม R ในไฟล์: `R001…` ว่างได้ ใช้แค่ภายในไฟล์ |
| `ชื่อกลุ่มตามกฎ` | ชื่อกลุ่ม R (ชื่อที่แสดงบนเว็บเมื่อรวมกลุ่ม) ว่างเมื่อไม่มีกลุ่ม R |

ข้อแนะนำสำหรับรอบถัดไป: ดูชื่อกลุ่มที่มีอยู่แล้วในระบบ (`/admin/types`) แล้วตั้งชื่อกลุ่มให้ตรงกัน ระบบจะจับคู่ชื่อที่ normalize แล้วกับกลุ่มเดิมได้ ไม่เกิดกลุ่มซ้ำ (ตัวอย่างที่เกิดแล้ว: "Dr.PONG 28D smart whitening drone acne activein serum Gen2" แยกเป็น 2 กลุ่ม)

## ไฟล์ที่ส่งเข้าระบบ

- CSV UTF-8 คอลัมน์ 14 ตัว: `รหัสสินค้า, namePrefix, ชื่อสินค้า, ราคา, ขาย, ชื่อร้านค้า, อัตราค่าคอมมิชชัน, คอมมิชชัน, ลิงก์สินค้า, ลิงก์ข้อเสนอ, รหัสกลุ่ม, ชื่อกลุ่ม, รหัสกลุ่มตามกฎ, ชื่อกลุ่มตามกฎ`
- `namePrefix` = ข้อความก่อน "Dr." เท่านั้น, `ชื่อสินค้า` = ตั้งแต่ "Dr." ไป — ระบบเก็บตามไฟล์ ไม่ตรวจว่าขึ้นต้นด้วย "Dr."
- ไฟล์รูปแบบเก่า (12 คอลัมน์ มี `วิธีจัดกลุ่ม`) **ถูกปฏิเสธ** ข้อมูลรูปแบบเก่าล้างทิ้งก่อนเริ่มรูปแบบนี้
- วางไฟล์ใน `inbox/` ที่ root ของโปรเจกต์ (ชื่อไฟล์ลงท้าย `.csv` ห้ามมี `/ \ : * ? " < > |` หรือ `..`)
- แถวใดผิด ทั้งไฟล์ถูกปฏิเสธ หน้าพรีวิวแสดงปัญหาตามเลขแถว

## ในระบบ

1. admin เปิด `/admin/inbox` → ดูพรีวิว: รายการใหม่ / ราคาเปลี่ยน (เดิม → ใหม่) / จะถูกซ่อน / จะรอตรวจ / กลุ่มใหม่ / จำนวนที่จะดึงจาก feed — ยังไม่บันทึกอะไร
2. กด "นำเข้าไฟล์นี้" (ไฟล์ย้ายไป `inbox/imported/`) หรือ "ทิ้งไฟล์" (ย้ายไป `inbox/rejected/`)
3. ระบบสร้างรหัสกลุ่มของตัวเอง (`PT000001`) ทั้งกลุ่ม E (`kind = NAME`) และกลุ่ม R (`kind = RULE`) และใช้กฎกลุ่ม/ราคา/สถานะตาม [README](../README.md#กฎการนำเข้า-สรุป) — โค้ดหลักอยู่ที่ `backend/src/main/java/com/snapshop/service/importing/ImportPlanner.java` และ `RulePlanner.java`
4. หลังนำเข้าเสร็จ ระบบดึง feed ให้ ([ดูด้านบน](#เมื่อไรที่ระบบดึง-feed)) โค้ดอยู่ที่ `backend/src/main/java/com/snapshop/service/feed/`
5. admin REVIEW กลุ่ม R ที่ `/admin/rule-groups` ([README](../README.md#review-กลุ่ม-r)): กลุ่ม E ที่ติ๊กรวมเข้ากลุ่ม R ทั้งกลุ่ม (`product_type.merged_into_type_id`) และรายการกลุ่ม R ทุกรายการผ่าน REVIEW
6. เว็บ user แสดงเฉพาะกลุ่มที่แสดง (กลุ่ม R ที่กลุ่ม E ถูกรวมเข้าไป ไม่เช่นนั้นกลุ่ม E) ที่มีรายการสถานะ OK ≥ 2 รายการ (view `public_product`); admin เห็นทั้งหมดและตัดสินรายการ REVIEW / ย้ายกลุ่ม / บันทึกเลิกขาย
7. รูปของกลุ่มบนหน้าแรก = รูปของ offer ที่ถูกสุดที่มีรูป; ไม่มี offer ไหนมีรูปเลย แสดง "ยังไม่มีรูป"

อัปโหลดไฟล์ตรงที่ `/admin/import` ยังใช้ได้

| 8 | ขยายไปสินค้าอื่น | ยังไม่ตอบ — ตอนนี้หมวดเดียว `DRPONG` (มีคอลัมน์ `category_code` รองรับ) |

## คำถามที่ยังเปิด

- ก่อนขึ้นระบบจริง: ยุบ migration V1–V5 (และที่เพิ่มต่อ) เป็นไฟล์เดียว ฐานข้อมูลจริงเริ่มจากว่าง
- สถานะ "สินค้าหมด" ยังดูจากคำในชื่อ ควรใช้ `stock` จาก feed แทนไหม (feed ไม่ดึงรายการที่ราคาเท่าเดิม stock จึงอาจค้าง)
- การผ่านอัตโนมัติเทียบกลุ่ม R กับกลุ่ม E **ภายในไฟล์** เท่านั้น ไม่ดูสมาชิกกลุ่ม R เดิมในฐานข้อมูล — รอบถัดไปที่กลุ่ม R เดิมได้สมาชิกใหม่ในกลุ่ม E อื่นอาจต้องทบทวน
- ยกเลิกการรวมกลุ่ม (unmerge) ยังไม่มี

- ชุดโปรโมชัน ("กด 2 ฟรี 1") และ Refill pack นับเป็นชนิดเดียวกับสินค้าปกติไหม
- เงื่อนไขของ Shopee Affiliate: อนุญาตให้ดึง feed อัตโนมัติ และนำข้อมูลสินค้า/รูปไปแสดงบนเว็บแค่ไหน (ผู้ใช้ต้องยืนยันก่อนเปิดใช้ `FEED_URL` จริง)
- ขยายไปสินค้าอื่น: คำค้นเดียวต่อรอบ หรือหลายร้าน/หลายหมวด
- admin หลายคน มีรหัสของตัวเองและ role (เช่น `UPLOADER` วางไฟล์/ดูพรีวิวได้อย่างเดียว)
- รายการที่ราคาไม่เปลี่ยนไม่ถูกดึง feed ใหม่ ต้องการปุ่ม "รีเฟรชทั้งหมด" สำหรับ stock/rating หรือไม่
