ฉบับปัจจุบัน (อัปเดต 2026-11-16 รอบ feed) ใช้แทนบรีฟเดิม (2026-11-12) ส่วนที่เปลี่ยนไปจากบรีฟดูได้ที่ [บันทึกการตัดสินใจ](#บันทึกการตัดสินใจ)
ศัพท์: [GLOSSARY.md](GLOSSARY.md) · กฎนำเข้าในระบบ: [README.md](../README.md#กฎการนำเข้า-สรุป)

## ภาพรวม

```
F1  ลิงก์ affiliate (พอร์ทัล Shopee Affiliate) ─ แยกชนิดสินค้า ─ ไฟล์ CSV ─ inbox/ ─ พรีวิว ─ นำเข้า ─┐
                                                                                                    │
                      ┌─────────────────── ระบบดึง feed ของ Shopee อัตโนมัติ (ราคา, ประเภทร้าน, รูป, ...) ◄┘
                      └─ เก็บในตาราง marketplace_product เดิม ─ API ─ เว็บ
```

| ขั้น | ทำอะไร | ใครทำ (ตอนนี้) | ผลลัพธ์ |
|---|---|---|---|
| F1 | กดปุ่ม "รับลิงก์แบบทีเดียวทั้งหมด" ในพอร์ทัล | ผู้ใช้ | ไฟล์ CSV (≤ 100 รายการต่อไฟล์) |
| แยกชนิดสินค้า | ใส่ รหัสกลุ่ม / ชื่อกลุ่ม / วิธีจัดกลุ่ม | Claude | ไฟล์พร้อมนำเข้า |
| ส่งเข้าระบบ | วางไฟล์ใน `inbox/` | Claude หรือผู้ใช้ | ไฟล์รอนำเข้า |
| พรีวิว + นำเข้า | ดูผลก่อน แล้วกดนำเข้าหรือทิ้ง ที่ `/admin/inbox` | admin | ข้อมูลใน PostgreSQL |
| ดึง feed | หลังนำเข้าเสร็จ ระบบหารายการที่ต้องดึงจาก feed แล้วเติมข้อมูล | ระบบ (อัตโนมัติ) | ราคาที่ขาด, ประเภทร้าน, รูป, stock, rating |

ข้อตกลง: Claude ไม่ใช้รหัสผ่านหรือคีย์ admin ของระบบ และไม่ทำ automation ที่พรางตัวเป็นคนบน Shopee
**F2 เลิกใช้แล้ว** (เดิมคืออ่านการ์ดสินค้าจากหน้าค้นหา ซึ่งผิดกฎ) ข้อมูลที่เคยมาจาก F2 มาจาก feed แทน

## F1 — ลิงก์ affiliate จากพอร์ทัล

- ปุ่ม "รับลิงก์แบบทีเดียวทั้งหมด" เลือกได้ครั้งละ ≤ 100 รายการ จึงได้หลายไฟล์ (ชุดตัวอย่าง 192 รายการ = 2 ไฟล์)
- คอลัมน์: `รหัสสินค้า, ชื่อสินค้า, ราคา, ขาย, ชื่อร้านค้า, อัตราค่าคอมมิชชัน, คอมมิชชัน, ลิงก์สินค้า, ลิงก์ข้อเสนอ`
- `ลิงก์สินค้า` = `https://shopee.co.th/product/{shopId}/{itemId}` (ระบบดึง shop_id จากตรงนี้ และตรวจว่า itemId ตรงกับรหัสสินค้า)
- `ลิงก์ข้อเสนอ` = ลิงก์ affiliate สั้น `s.shopee.co.th/...` สร้างใหม่ทุกครั้งที่กด จึงไม่นับเป็นการเปลี่ยนแปลงของสินค้า
- ไม่ใช้ Sub_id (ยังไม่จำเป็นเมื่อมีหมวดเดียว; ใช้แยกยอดคลิก/ออเดอร์ตามตำแหน่งปุ่มได้ในอนาคต)
- ข้อควรระวัง: ราคาบางแถวเป็นตัวย่อ ("1.0พัน") — ระบบรอราคาจาก feed (ดู [ราคา](#ราคา)), ยอดขายส่วนใหญ่เป็นตัวย่อ ("200พัน+"), คอมมิชชันมี "฿", อัตรามี "%"

## Feed ของ Shopee (แทน F2)

- ลิงก์ feed เป็นความลับ ตั้งผ่านตัวแปรสภาพแวดล้อม `FEED_URL` (ไม่เก็บใน repo); ว่าง = ปิดการดึงอัตโนมัติ
- feed เป็น CSV ขนาดราว 4 GB (~20 ล้านแถว) ระบบอ่านจากลิงก์โดยตรงแบบ stream ไม่เก็บไฟล์ลงเครื่อง และ**หยุดอ่านทันทีเมื่อเจอครบทุกรายการที่ขอ**
- คอลัมน์ที่ใช้: `itemid, shopid, price` (ก่อนลด), `sale_price` (หลังลด), `stock, item_rating, shop_rating, is_official_shop, is_preferred_shop, image_link`
- ประเภทร้านมาจาก feed: `Official shop` → Mall, ไม่ใช่แต่ `Preferred shop` → ร้านแนะนำ, นอกนั้น → ทั่วไป (ข้อมูลประเภทร้านที่ scrape มาก่อนหน้าถูกล้างทิ้ง)
- รูปมาจาก `image_link` (เก็บลิงก์ ไม่ดาวน์โหลดรูป); รายการไม่มีรูปแสดง "ยังไม่มีรูป"; ถ้า feed ไม่มีรูปของรายการนั้น ไม่ทับรูปเดิมที่มี
- ถ้า `shopid` ใน feed ไม่ตรงกับที่เก็บไว้ ข้ามแถวนั้น

### เมื่อไรที่ระบบดึง feed

หลังนำเข้า F1 สำเร็จ (commit แล้ว) ระบบดึง feed ให้รายการเหล่านี้: รายการใหม่, รายการที่ราคา F1 เปลี่ยน, รายการที่ราคา F1 เป็นตัวย่อ (เทียบเองไม่ได้ จึงดึงทุกรอบ), และรายการที่ยังรอราคา
รายการที่ราคาเท่าเดิมไม่ถูกดึงใหม่ (stock/rating จึงไม่สดเอง) — admin กด "ดึงรายการที่ค้างจากฟีด" ที่หน้า `/admin` เพื่อดึงรายการที่ยังรอราคาหรือไม่เคยดึงได้
ทำทีละงานบนเธรดเดียว นอก transaction แล้วเขียนผลใน transaction สั้น ๆ ที่ใช้ล็อกเดียวกับการนำเข้า ทุกรอบบันทึกใน `feed_sync_run` (เสร็จ / ไม่ครบ / ถูกจำกัด 429 / ล้มเหลว) แสดงที่หน้า admin ระบบไม่ลองซ้ำเอง (เคยโดน 429 เมื่อโหลดถี่)

### ราคา

- F1 ราคาเป็นตัวเลข: ใช้ราคา F1 ตามเดิม feed ไม่เทียบและไม่แทนที่ (ผู้ใช้เทียบเองที่หน้าเว็บ)
- F1 ราคาเป็นตัวย่อ: แถวสถานะ `PRICE_PENDING` (ซ่อนจากเว็บ ไม่ใช่ REVIEW) → feed ให้ `sale_price` แล้วเป็น `OK`; รอบถัดไปถ้า `sale_price` ต่างจากที่เก็บไว้ จะเกิดเวอร์ชันราคาใหม่ (ประวัติราคา)
- feed ไม่มี `sale_price` หรือไม่พบรายการ: ยังเป็น `PRICE_PENDING` ต่อไป

## แยกชนิดสินค้า

กลุ่ม = รายการสินค้าชนิดเดียวกันที่ขายหลายร้าน ใช้เปรียบเทียบราคา กฎ 2 ชั้นตามลำดับ:
1. **ชื่ออังกฤษตรงกัน:** normalize ชื่อ (ตัวพิมพ์เล็ก, ตัดเครื่องหมาย/ช่องว่างซ้ำ, ตัดข้อความโปรโมชันภาษาไทย) ตรงกันถือเป็นชนิดเดียวกัน **ขนาดต่างกันถือเป็นชนิดเดียวกัน** (15 ml กับ 16 ml)
2. **กฎคำระบุสูตร:** ใช้คำ/รหัสสูตรในชื่อ (activeIN, U9.9, MC1, G89, P55, 28D, 711, BarrierX, Retinal-X, Bakuchiol, Astaxanthin ฯลฯ) รวมชื่อที่ต่างกันเล็กน้อย

คอลัมน์ที่เพิ่มในไฟล์:

| คอลัมน์ | ค่า |
|---|---|
| `รหัสกลุ่ม` | ป้ายในไฟล์: `E001…` (ชื่ออังกฤษตรงกัน), `R001…` (กฎคำระบุสูตร), `U001…` (ไม่มีคู่) — **ใช้แค่ภายในไฟล์นั้น** ระบบไม่เก็บ |
| `ชื่อกลุ่ม` | ชื่อของชนิดสินค้า |
| `วิธีจัดกลุ่ม` | `ชื่ออังกฤษตรงกัน` / `ตามกฎคำระบุสูตร` / `ไม่มีคู่` |

ข้อแนะนำสำหรับรอบถัดไป: ดูชื่อกลุ่มที่มีอยู่แล้วในระบบ (`/admin/types`) แล้วตั้งชื่อกลุ่มให้ตรงกัน ระบบจะจับคู่ชื่อที่ normalize แล้วกับกลุ่มเดิมได้ ไม่เกิดกลุ่มซ้ำ (ตัวอย่างที่เกิดแล้ว: "Dr.PONG 28D smart whitening drone acne activein serum Gen2" แยกเป็น 2 กลุ่ม)

## ไฟล์ที่ส่งเข้าระบบ

- CSV UTF-8 คอลัมน์ 12 ตัว: `รหัสสินค้า, ชื่อสินค้า, ราคา, ขาย, ชื่อร้านค้า, อัตราค่าคอมมิชชัน, คอมมิชชัน, ลิงก์สินค้า, ลิงก์ข้อเสนอ, รหัสกลุ่ม, ชื่อกลุ่ม, วิธีจัดกลุ่ม`
- คอลัมน์ `ประเภทร้านค้า` และ `ลิงก์รูปภาพ` ของไฟล์รุ่นเก่า **ไม่ใช้แล้ว** (ไฟล์เก่าที่ยังมีสองคอลัมน์นี้นำเข้าได้ ระบบข้ามไป)
- **ต้องคงชื่อสินค้าเต็ม** อย่าตัดข้อความก่อน "Dr." ออก ระบบแยก `name_prefix` / `name_core` เอง
- วางไฟล์ใน `inbox/` ที่ root ของโปรเจกต์ (ชื่อไฟล์ลงท้าย `.csv` ห้ามมี `/ \ : * ? " < > |` หรือ `..`)
- แถวใดผิด ทั้งไฟล์ถูกปฏิเสธ หน้าพรีวิวแสดงปัญหาตามเลขแถว

## ในระบบ

1. admin เปิด `/admin/inbox` → ดูพรีวิว: รายการใหม่ / ราคาเปลี่ยน (เดิม → ใหม่) / จะถูกซ่อน / จะรอตรวจ / กลุ่มใหม่ / จำนวนที่จะดึงจาก feed — ยังไม่บันทึกอะไร
2. กด "นำเข้าไฟล์นี้" (ไฟล์ย้ายไป `inbox/imported/`) หรือ "ทิ้งไฟล์" (ย้ายไป `inbox/rejected/`)
3. ระบบสร้างรหัสกลุ่มของตัวเอง (`PT000001`) และใช้กฎกลุ่ม/ราคา/สถานะตาม [README](../README.md#กฎการนำเข้า-สรุป) — โค้ดหลักอยู่ที่ `backend/src/main/java/com/snapshop/service/importing/ImportPlanner.java`
4. หลังนำเข้าเสร็จ ระบบดึง feed ให้ ([ดูด้านบน](#เมื่อไรที่ระบบดึง-feed)) โค้ดอยู่ที่ `backend/src/main/java/com/snapshop/service/feed/`
5. เว็บ user แสดงเฉพาะกลุ่มที่มีร้านขายได้ ≥ 2 ร้าน (view `public_product`); admin เห็นทั้งหมดและตัดสินรายการ REVIEW / ย้ายกลุ่ม / บันทึกเลิกขาย
6. รูปของกลุ่มบนหน้าแรก = รูปของ offer ที่ถูกสุดที่มีรูป; ไม่มี offer ไหนมีรูปเลย แสดง "ยังไม่มีรูป"

อัปโหลดไฟล์ตรงที่ `/admin/import` ยังใช้ได้
